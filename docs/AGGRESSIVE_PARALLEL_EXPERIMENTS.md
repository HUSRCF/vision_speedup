# 更大范围的并行实验：2026-10-28

正式采用的双卡 V2 为 **312.462900 秒**，五项历史有效运行合计 **867.455206 秒**。与用户提供的 653.75 秒快照相比，相差约 213.71 秒；其中 V2 相差约 106.79 秒。非 V2 解码优化和双卡 V2 均已通过官方 103 视频复核并更新提交材料。

## 为什么转向两张 GPU

当前[参赛手册](../problem/PARTICIPANT_HANDBOOK.md)“可尝试方向”明确列出分项内部多 GPU 并行。各实验明确使用两张 A800，不能作为单卡加速结果。交互轮次存在状态和图像反馈依赖，仍逐轮执行；没有减少轮数、50 个采样步或 16 帧。

两卡 P2P 测得约 184 GB/s；每卡独立 CUDA Graph 可并行，但同进程的统一跨卡 Graph 捕获失败。因此采用两进程、每进程一张可见 GPU、每进程独立 Graph，通过捕获在图中的 NCCL 交换结果。单卡可见拓扑也保留了原始输入缓存的 RNG 检查。

启动时保留 `team07_env.sh` 的环境，包括 `PYTHONHASHSEED=123` 和 TMPDIR。最初原有 Kahan kernel 的编译指纹检查失败，没有取消或放宽该检查；恢复原启动环境后，两张卡上、NCCL 初始化前后的 14 项指纹全部匹配。

进一步核对发现，七种 Kahan cubin 的实际指令、常量与参数 ABI 区段均相同，差异仅在编译调试信息记录的源码绝对路径。见 `cubin-source-path-debug-proof-all7.json`。这揭示了现有生产实现的冷缓存移植限制：完整 cubin 哈希依赖历史编译缓存和源码路径。CPU 对照未能将此独立归因于哈希种子或 TMPDIR，因此不作该因果声称；也没有为了新实验绕过原检查。移到全新缓存的环境时仍需处理这一复现问题。

## 完整 world denoiser 检查

单独把 C640 GEGLU 分配到两卡，随后 all-gather 两份 Half 中间结果：单算子合成测试更快，但真实完整 world denoiser 反而慢约 0.93/4.59 ms，故关闭该路径。

随后将 **20 个 C320/C640 FFN** 的 GEGLU 和最终残差投影一起拆分，每卡计算独立的一半输出行，只在 FFN 末尾 all-gather 一份 FP32 输出。保留原 shader、K64 累加和舍入顺序、完整逻辑形状、原始缓存 owner、权重版本与设备 Count 分支。三个最终输出在原始输入、新输入、570 个 Linear 和 782 个归一化 affine 参数修改、清零、恢复的六种检查中全部逐位一致，RNG 与恢复后的基线也一致。

包含 NCCL 通信的六对完整 world denoiser 计时全部加速，两 rank 的节省中位数分别为 **13.157883 ms / 9.347595 ms**。这个 20 FFN 版本只有模型前向诊断；完整视频测试采用下述扩大后的 32 FFN 加 88 时间卷积版本。

精确对应上述证据的代码位于 [`validated-c320-c640`](../experiments/nccl-ffn-209/validated-c320-c640)。扩大到 32 个 world FFN 的首轮被外部 GPU 进程打断，其时间不采用。修正占卡阶段的重试分类后，干净重测通过六组逐位一致检查，两 rank 节省中位数为 **21.955582 / 18.664948 ms**，代码位于 [`validated-world-32`](../experiments/nccl-ffn-209/validated-world-32)。

再叠加 **88 个时间卷积**的输出通道拆分，保持完整输入通道、16 帧和原始 K 累加顺序，六组检查仍逐位一致，两 rank 节省中位数为 **25.524734 / 22.738937 ms**。对应代码与完整报告见 [`validated-world-ffn-temporal`](../experiments/nccl-ffn-209/validated-world-ffn-temporal)。这里仅验证 world 路径；相同文件内的 decision hook 不因此获得资格。

decision FFN 拆分的第一组实际模型检查出现相对误差 **0.000190745**、最大绝对误差 **0.001086593**，未通过逐位检查，尚无完整视频质量结论。缩小矩阵尺寸后 vendor GEMM 的数值路径需要进一步核对。

新的双卡推理入口在原始 `PROCESS_START_TIME` 之后启动 helper，通信初始化、双模型加载、图捕获、全部输出以及 helper 退出均在 rank 0 原始计时内。首个单轮测试在 NCCL 关闭时卡住，GDB 确认仍存活的 CUDA Graph 持有通信回调；修正为先关闭图 owner、reset 图，再关闭进程组。修复后的单轮测试完成两阶段各 50 步，两 rank 的三个视频 SHA256 相同，并通过整段独占检查。完整 11 轮两阶段各 550 步测得 **312.462900 秒 / PSNR 29.675324786 dB**，比单卡基线快 **4.311496 秒**。23 个视频与另一 rank 及原单卡基线全部 SHA256 相同，随后通过官方五项 103 视频复核并采用。

world CUDA 时间从 172.914277 降到 161.962414 秒，decision 从 134.876197 增到 137.974908 秒；启动、传输和退出成本进一步抵消收益。因此这仍是小幅端到端改进，不能用单步微测推算大幅总加速。两卡最高温度 **73°C / 59°C**；完整遥测和原始单项结果见 [`nccl-timed-full-r2`](../results/aggressive-20261028/nccl-timed-full-r2)，源码与计时证明见 [`timed-entry`](../experiments/nccl-ffn-209/timed-entry)。

整段 SpatialTransformer 的直接 8+8 帧拆分也已测试。全局动作帧编号、缓存隔离和恢复通过 64 项 CPU 检查；六组真实模型误差最大约 9.13e-5。但每次前向反而慢 **9.14 / 11.85 ms**，未采用。后续会核对缩小形状后失去的快速调度，研究保留完整逻辑形状的分工。

两卡采样窗口约 34–41°C、核心 1410 MHz，见证据中的 `telemetry-window-only.json`；仅代表该窗口，不能替代完整运行的温度、功耗和频率记录。

## 其余四项与精度失败记录

Z1 最初只对不会回灌下一轮的 world 视频帧使用缓存 Half VAE、批量解码，完整结果为 **172.482165 秒 / PSNR 40.078446 dB**。随后扩展到 decision 展示视频；两个反馈帧始终使用原始 FP32 解码器和原始 TF32 标志，主干和采样器不变。

| 已采用分项 | 原成绩 s | 新成绩 s | PSNR dB |
|---|---:|---:|---:|
| Z1 堆箱 | 175.139262 | 167.819341 | 40.074914 |
| 清理铅笔 | 122.080670 | 117.077862 | 36.537127 |
| G1 相机装箱 | 166.378951 | 160.897537 | 26.107156 |

三项均完成规定轮数与全部视频、整段独占记录及官方 103 视频汇总复核，合计节省 **17.804143 秒**。源码见 [`nonv2-vae-all-display`](../experiments/nonv2-vae-all-display)。汇总目录用硬链接引用各实际运行的不可变视频，前后逐文件核对 SHA256；未改写视频、分项耗时或官方验证工具。双臂堆箱的同策略完整测试还在等待空卡。

Z1 cuDNN 搜索加 Conv2d 的候选为 181.004042 秒；channels-last 候选为 209.011749 秒，均较慢。不是有效优化。

两条降低精度的完整 V2 路线均失败：时间注意力三个补偿乘积为 **316.512409 秒 / 22.759869 dB**；空间 Transformer 前 14 帧 Half dense/attention、FP32 norm/残差、后 2 帧保留原路径为 **311.596807 秒 / 21.895641 dB**。它们都完成规定工作量并独占运行，但不满足严格大于 25 dB 的质量要求，不采用。
