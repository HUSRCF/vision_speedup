# 已采用：G1 双卡时间分片与单次主机权重搬运

G1正式成绩更新为 **155.314304秒 / PSNR26.107156332dB**，比历史正式160.897537秒少 **5.583233秒**。新方案两次同GPU完整对照分别净省 **3.435458／3.655682秒**。23视频与原正式及另一rank的SHA256全部相同，全部103视频重新通过官方校验。本机`GPU/runtime.log`、`GPU/result.json`已备份后更新，网站没有提交。

五项现在均使用双卡，分项合计 **765.731042秒**。JSON的`external_wall_s`为765.815235秒，包含原汇总格式的额外计时。五项来自各自完整运行后的官方汇总，不是一次连续五项进程测量。

## 保留数学路径，扩大已有汇合覆盖

本版本保留67文件版本的原生Half GEMM行网格、原GEGLU CUBIN、75次空间和32次融合时间attention／阶段。16个时间内部块按空间位置分片，每个位置保留完整16帧；完整5D GroupNorm在分片之前执行。每次denoiser仍31次汇合，没有增加通信边界。FP32 feedback head、全部11轮、每阶段每轮50步、23视频保留。

此前67文件完整模型前向有收益，但整项仅少0.119988秒。实测双卡`model_to_gpu`阶段为5.733544秒，成为明确的额外成本。本轮在原59文件基线上增加到68文件；原数学源码、67文件版本的全部数值helper均保持SHA一致，仅改设备搬运与计时内生命周期接点。

## 权重传输

`nccl_root_model_move.py`收集注册参数与buffer，按dtype分组并构造有界CUDA桶。只有rank0执行CPU到GPU复制，随后通过原NCCL进程组广播给rank1。保留参数对象、共享别名、dtype、shape、contiguous stride，每个张量起点256字节对齐，保持原生内核的对齐分派条件。

真实模型包含3576个唯一张量，67个桶，共16,718,118,720字节（包含桶内对齐）。rank0／1的搬运报告为2.668139／2.668561秒；整个原`model_to_gpu`阶段为 **2.922509秒**，相比67文件版本少 **2.811035秒**。元数据核对、分配、广播、同步都在原进程计时内。

广播后保留标准`model.cuda()`生命周期，使Lightning设备跟踪更新；此时注册张量已经在CUDA。非连续或不支持dtype时，双方回到原生`.cuda()`。真实G1没有走回退路径。

首版68完整试跑在第一次推理因Lightning设备标记仍为CPU而中止，没有有效成绩。修复后增加`_apply`设备跟踪回归检查。三个独立合成轮次保留：r1检验搬运／别名，r2增加256字节对齐，r3增加标准CUDA生命周期。两rank各六状态，包括rank1故意使用不同CPU源值，最终收到rank0位值；检查精度、别名、空张量、scalar、bool／整数buffer、输入变化／清零／恢复、回退及RNG。合成资格不替代完整视频质量。
