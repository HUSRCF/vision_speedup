# FP16、缩放与量化残差：2026-10-28

本轮尚无同时满足局部精度门槛和加速要求的新算术候选，正式提交保持 **V2 301.930663 秒、五项合计 850.836587 秒**。这不排除更好的分组、异常通道保护或融合实现；下面的结论限定于已测的三种实际 FFN 矩阵形状。

## 当前大矩阵已经使用 FP16 Tensor Core

原实现将输入拆成 `XH + XL / 2048`，静态权重拆成 `(WH + WL / 2048) / 256`，通过两个或三个 FP16 Tensor Core 乘积补偿误差，并保留短 K64 的 FP32 舍入、累加和残差输出。`WL` 为零时原实现已跳过第三个乘积。

因此减少补偿乘积、转换和访存才是进一步加速的机会。单纯把输出 dtype 改成 FP16，或增大一个全局 scale，不能证明计算更快或精度足够。

本轮借鉴了 [SmoothQuant 的通道平衡](https://arxiv.org/abs/2211.10438)与 [LLM.int8 的混合精度分解](https://arxiv.org/abs/2208.07339)，没有复现这两篇论文的完整算法，也没有将它们在语言模型上的质量结论用于视频模型。扩散模型还存在随 timestep 改变的激活分布，[Q-Diffusion](https://arxiv.org/abs/2302.04304)因此采用跨 timestep 校准；本轮只有一个实际调用样本，尚未覆盖这个范围。

## 测量范围

固定原始 209 个生产源码、全部原 flags 和 native cache owner，在 world 第三个公开 denoiser 调用后另做一次原始 eager 前向，仅在内存中克隆三个实际残差 GEMM 的操作数。未读取历史原始操作数文件，未导出张量、视频或权重。

每种形状测量单乘积 FP16、原补偿的对照、INT8 残差补偿、K64 分组普通／二次幂 scale，以及三个 alpha 的输入通道平衡。通道平衡使用本次激活的逐通道最大值和权重逐通道最大值，输入乘 `s`、权重除 `s`；alpha 为 0.25、0.5、0.75。这只是一份样本的局部校准。

候选与实际原 kernel 进行六对交替计时，每种条件取七个样本，每个样本重放十次。动态打包进入每次 CUDA Graph 重放，静态权重准备单列记录；其中首次 JIT 可能进入该静态准备记录，不能视为纯打包耗时。r5 的 N64 tile 使用与原实现相同的流水深度 3；N128 实验明确使用深度 2。

精度证据包括全部输出误差，以及 16 行 × 8 列输出、完整 K 维度的 FP64 oracle。下表相对 L2 以去掉 bias 和 residual 的原 GEMM 输出为分母，防止大 residual 掩盖误差。原补偿对照逐位相同；动态输入、非零权重低位回退、恢复后的基线、三个模型输出、RNG 与全部模型参数版本检查通过。

## r5 实测结果

| M / N / K | 单次 FP16 相对误差 | K64 分组 scale 相对误差 | 通道平衡最佳相对误差 | FP16 + INT8 残差相对误差 | 最快 INT8 候选相比原 kernel |
|---|---:|---:|---:|---:|---:|
| 640 / 1280 / 5120 | 1.2980e-4 | 1.0501e-4 | 1.8380e-4 | 9.1198e-7 | 慢 0.094208 ms |
| 2560 / 1280 / 5120 | 1.6866e-4 | 1.9198e-4 | 2.3830e-4 | 2.4861e-6 | 慢 0.352870 ms |
| 40960 / 320 / 1280 | 1.9312e-4 | 2.2535e-4 | 2.7188e-4 | 2.7066e-6 | 慢 0.451789 ms |

将全局 scale 从 1 改为 16、256、4096，三种输入的重建相对误差始终约为 **2.06e-4～2.07e-4**。部分极小值确实得到改善，但总误差几乎不变，说明这批输入主要受尾数精度限制。二次幂分组 scale 也基本保留了单次 FP16 的误差量级。

单次 FP16 每个算子可以省约 **0.087～0.312 ms**，但未通过本诊断的局部精度筛选。通道平衡增加了权重量化误差，没有稳定改善。INT8 只近似已缩小的残差乘积，误差明显下降，但混合 MMA、尺度读取和动态打包成本使当前实现更慢。

r3 将权重低位 predicate 留在 K 循环内，连原补偿对照都明显变慢。r4 将这个 predicate 移到循环外，r5 再对齐流水深度；这些修正改善了对照速度，但没有让 INT8 候选快于已优化的生产 kernel。r3、r4、r5 的精确源码和证据均保留，不能将早期实现的负收益推广到所有 INT8 方案。

本诊断的 `numerical_eligible_for_model_only` 仅表示通过预设的局部误差筛选，不代表视频 PSNR 合格。此次未安装新算术到完整模型，也未做这些候选的完整视频测试；目前没有依据替换正式实现。静态 INT8 权重缓存的生产版本刷新与生命周期也尚未实现。

## 同期 decision 分片验证

新的 decision 版本保留完整 Python 形状、vendor GEMM 尺寸与原精度标志，仅在原 Triton 调度之下分配独立行和帧。原 K/V pack 为展平的 `[B*N*H,64]`，指针切片前恢复 batch 视图；CPU 检查补入该真实布局。

54 项 CPU 检查和六组完整模型的输入／570 Linear／782 norm 参数修改、清零、恢复检查通过，三个最终 FP32 输出全部逐位相同。两个 rank 的完整 decision 前向节省中位数为 **19.006966 / 15.908356 ms**，包含通信。这只是 decision 模型诊断，尚未与当前 world 分片组合完成正式 V2，不能据此宣称正式成绩下降。
