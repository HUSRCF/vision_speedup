# FP16、缩放与量化残差：2026-10-28

r3–r5 尚无同时满足局部精度门槛和加速要求的新算术候选；测量时正式提交为 **V2 301.930663 秒、五项合计 850.836587 秒**。后续两阶段并行已将正式结果改为 **289.486308 / 838.392232 秒**，新算术仍未采用。下面的算术结论限定于已测的三种实际 FFN 矩阵形状，后续扩大残差分组的结果见文末。

## 当前大矩阵已经使用 FP16 Tensor Core

原实现将输入拆成 `XH + XL / 2048`，静态权重拆成 `(WH + WL / 2048) / 256`，通过两个或三个 FP16 Tensor Core 乘积补偿误差，并保留短 K64 的 FP32 舍入、累加和残差输出。`WL` 为零时原实现已跳过第三个乘积。

因此减少补偿乘积、转换和访存才是进一步加速的机会。单纯把输出 dtype 改成 FP16，或增大一个全局 scale，不能证明计算更快或精度足够。

本轮借鉴了 [SmoothQuant 的通道平衡](https://arxiv.org/abs/2211.10438)与 [LLM.int8 的混合精度分解](https://arxiv.org/abs/2208.07339)，没有复现这两篇论文的完整算法，也没有将它们在语言模型上的质量结论用于视频模型。扩散模型还存在随 timestep 改变的激活分布，[Q-Diffusion](https://arxiv.org/abs/2302.04304)因此采用跨 timestep 校准；本轮只有一个实际调用样本，尚未覆盖这个范围。

## 测量范围

固定原始 209 个生产源码、全部原 flags 和 native cache owner，在 world 第三个公开 denoiser 调用后另做一次原始 eager 前向，仅在内存中克隆三个实际残差 GEMM 的操作数。未读取历史原始操作数文件，未导出张量、视频或权重。

每种形状测量单乘积 FP16、原补偿的对照、INT8 残差补偿、K64 分组普通／二次幂 scale，以及三个 alpha 的输入通道平衡。通道平衡使用本次激活的逐通道最大值和权重逐通道最大值，输入乘 `s`、权重除 `s`；alpha 为 0.25、0.5、0.75。这只是一份样本的局部校准。

候选与实际原 kernel 进行六对交替计时，每种条件取七个样本，每个样本重放十次。动态打包进入每次 CUDA Graph 重放，静态权重准备单列记录；其中首次 JIT 可能进入该静态准备记录，不能视为纯打包耗时。r5 的 N64 tile 使用与原实现相同的流水深度 3；N128 实验明确使用深度 2。

精度证据包括全部输出误差，以及 16 行 × 8 列输出、完整 K 维度的 FP64 oracle。下表相对 L2 以去掉 bias 和 residual 的原 GEMM 输出为分母，防止大 residual 掩盖误差。原补偿对照逐位相同；动态输入、非零权重低位回退、恢复后的基线、三个模型输出、RNG 与全部模型参数版本检查通过。

## r5 实测结果

| M / N / K | 单次 FP16 相对误差 | K64 分组 scale 相对误差 | 通道平衡最佳相对误差 | FP16 + INT8 残差相对误差 | 最快 INT8 候选相比原 kernel |
|---|---:|---:|---:|---:|---:|
| 640 / 1280 / 5120 | 1.2980e-4 | 1.0501e-4 | 1.8380e-4 | 9.1198e-7 | 慢 0.094208 ms |
| 2560 / 1280 / 5120 | 1.6866e-4 | 1.9198e-4 | 2.3830e-4 | 2.4861e-6 | 慢 0.352870 ms |
| 40960 / 320 / 1280 | 1.9312e-4 | 2.2535e-4 | 2.7188e-4 | 2.7066e-6 | 慢 0.451789 ms |

将全局 scale 从 1 改为 16、256、4096，三种输入的重建相对误差始终约为 **2.06e-4～2.07e-4**。部分极小值确实得到改善，但总误差几乎不变，说明这批输入主要受尾数精度限制。二次幂分组 scale 也基本保留了单次 FP16 的误差量级。

单次 FP16 每个算子可以省约 **0.087～0.312 ms**，但未通过本诊断的局部精度筛选。通道平衡增加了权重量化误差，没有稳定改善。INT8 只近似已缩小的残差乘积，误差明显下降，但混合 MMA、尺度读取和动态打包成本使当前实现更慢。

r3 将权重低位 predicate 留在 K 循环内，连原补偿对照都明显变慢。r4 将这个 predicate 移到循环外，r5 再对齐流水深度；这些修正改善了对照速度，但没有让 INT8 候选快于已优化的生产 kernel。r3、r4、r5 的精确源码和证据均保留，不能将早期实现的负收益推广到所有 INT8 方案。

本诊断的 `numerical_eligible_for_model_only` 仅表示通过预设的局部误差筛选，不代表视频 PSNR 合格。此次未安装新算术到完整模型，也未做这些候选的完整视频测试；目前没有依据替换正式实现。静态 INT8 权重缓存的生产版本刷新与生命周期也尚未实现。

源码见 [`experiments/fp16-scalar-residual-209`](../experiments/fp16-scalar-residual-209)，原始统计、计时与模型恢复证明见 [`results/aggressive-20261028/fp16-scalar-residual-209`](../results/aggressive-20261028/fp16-scalar-residual-209)。

## 同期 decision 分片验证

新的 decision 版本保留完整 Python 形状、vendor GEMM 尺寸与原精度标志，仅在原 Triton 调度之下分配独立行和帧。原 K/V pack 为展平的 `[B*N*H,64]`，指针切片前恢复 batch 视图；CPU 检查补入该真实布局。

54 项 CPU 检查和六组完整模型的输入／570 Linear／782 norm 参数修改、清零、恢复检查通过，三个最终 FP32 输出全部逐位相同。两个 rank 的完整 decision 前向节省中位数为 **19.006966 / 15.908356 ms**，包含通信。随后与 world 分片组合完成独立两阶段逐位检查及正式 V2，完整结果为 **289.486308 秒**，详见 [并行实验记录](AGGRESSIVE_PARALLEL_EXPERIMENTS.md)。

## 扩大 INT8 残差分组：后续实验

新的原型按 K256、K1024 或完整 K 缩放，在组内用 INT32 累加 INT8 MMA，结束一组才解量化。FP16 主项仍在原 K64 边界求和，但主项与补偿改为分开累加后相加，因此这是新的近似算术。动态 pack 成本继续计入；仍检查实际操作数、FP64 样本、非零权重低位的原路径回退，以及模型输出、RNG 和参数恢复。

三种形状、六种分组／N tile 组合共 18 个新配置，另有三个原补偿对照。`[640,1280,5120]` 的完整 K 分组、N128 tile 相对误差 **3.24635e-6**，六对测量均更快，中位数仅省 **0.003226 ms**。`[2560,1280,5120]` 的 K1024／完整 K 分组分别可省约 **0.0454 / 0.1046 ms**，但相对误差升至 **6.4830e-6 / 1.0703e-5**，未通过原预设的 6e-6 局部筛选；没有将它们标为精度合格。`[40960,320,1280]` 仍全部更慢。

扩大分组显著缩小了前版的负收益，但目前只有一个微小局部正收益，没有完整模型或视频质量结论。下一步可以测试分离设备 predicate 的快／回退 kernel、K512 组和 tile 组合，并评估与 producer 融合的收益；不能将微秒级单算子结果外推为正式加速。

精确源码与 21 项测量见 [`fp16-grouped-residual-209`](../experiments/fp16-grouped-residual-209) 和[结果目录](../results/aggressive-20261028/fp16-grouped-residual-209)。

精确代码见 [`experiments/nccl-spatial-decision-209`](../experiments/nccl-spatial-decision-209)，完整报告见 [`results/aggressive-20261028/nccl-spatial-decision-209`](../results/aggressive-20261028/nccl-spatial-decision-209)。

## 当前双卡形状与仅残差通道缩放

两轮后续测量均重新采集原始 209 源码模型的实际操作数，在内存中取第一张卡实际处理的半行视图：`[320,1280,5120]`、`[1280,1280,5120]`、`[20480,320,1280]`。未读取历史原始操作数文件，也未序列化新的操作数。比较基准保留原逻辑调用选择的 BM 与流水深度，因此中间形状的原 BM 仍为 64。

**r2** 将 `LowCount==0` 的 INT8 快路径与 `LowCount!=0` 的原三次 Half 回退拆成两个 kernel，两个设备 predicate、两次启动和每次输入打包全部进入计时。测试 K512/K1024/完整 K、BM32/64/128、BN64/128 和流水深度 2/3，共 42 个新配置及三个原补偿对照。中间形状的 K512、BM64/BN128、深度 3 同时通过局部误差与六对正收益门槛，省 **0.004608 ms**；另两种形状没有这样的候选。

**r3** 保留原 `XH @ WH` 和 K64 的 FP32 主项求和，仅平衡 INT8 残差 `XL @ WH` 的 K 通道。静态通道乘数为 `wmax**(1-alpha) / xlmax**alpha`，输入低位乘此值、残差权重除以此值；原 Half 主乘积不经过这个乘数。通道乘数从该次实际激活样本校准，alpha 测试 0.25/0.5/0.75/1。只在中间形状测试 K512/K1024/完整 K 及深度 2/3，共 24 个新配置；另有三种形状各一个原补偿对照。

| 中间形状的候选 | 残差分组 / 深度 | 去掉 residual 后的相对 L2 | 中位每次节省 | 局部筛选 |
|---|---:|---:|---:|---|
| r2，无通道平衡 | 512 / 3 | 5.17451e-6 | 0.004608 ms | 通过 |
| r2，无通道平衡 | 5120 / 2 | 1.03897e-5 | 0.046131 ms | 未通过 |
| r3，残差 alpha=0.5 | 5120 / 2 | 4.98374e-6 | 0.041933 ms | 通过 |
| **r3，残差 alpha=0.5** | **5120 / 3** | **4.98374e-6** | **0.077210 ms** | **通过** |

最佳候选的原 GEMM 约 **0.358 ms**，候选约 **0.281 ms**，六对计时均更快，中位加速比 **1.274 倍**，耗时降低约 **21.5%**。这包含动态输入量化与两个 predicate kernel 的启动；静态权重量化、首样本校准和首次 JIT 成本没有进入每次重放，尚未完成其生产缓存与版本刷新管理，不能据此宣称完整进程也获得相同比例收益。

预设的筛选仍是去掉 bias/residual 后相对 L2 不超过 6e-6、FP64 样本相对误差不超过 1e-5。最佳候选的 FP64 样本相对误差为 **3.57889e-6**，最大绝对输出差异 **2.47955e-5**。输入低位乘 0.75 后的重新计算、非零权重低位的逐位回退、原输出／RNG／参数版本恢复检查通过。相对误差与基准比较，不能视为严格 FP32 等价。

通道缩放在这份样本上确实改善了残差量化误差；此前将通道平衡直接用于主 Half 乘积的结果仍然不佳。这一轮尚未包含完整模型、跨 timestep 校准或完整 V2 PSNR，后续整网检查见下一节。正式成绩仍为 **289.486308 秒 / 29.675324786 dB**，五项合计 **838.392232 秒**。

## 完整 world 前向：第一次接入验证

随后在单张 A800 上将 alpha=0.5、完整 K 分组、BM64/BN128、深度 3 接入原始 209 源码的完整 world denoiser，选中 **10 次 `[2560,1280,5120]` FFN 输出投影**。其他形状和 decision 不变。每个原 Half 权重 owner 从第一次 eager 激活计算一次通道乘数；校准固定，后续每次重放均重新打包输入和权重，权重打包成本也进入整网计时。因此这里没有依赖尚未实现的静态量化权重刷新机制。

原 23 个 numerical SGEMM 与 45 个 head cache owner 保留。六组初始输入、输入变化、570 个 Linear 加 782 个 norm 参数修改／清零／恢复均通过预先设定的 0.002 gross gate；原模型基准和 RNG 恢复逐位正常。初始视频输出相对 L2 **2.13673e-5**，state 输出 **3.55792e-5**，action 输出逐位相同。这是近似路径，不是 FP32 逐位等价。

六对完整 denoiser 计时均更快：基准约 **291.3 ms**，候选约 **290.3–290.5 ms**，每次中位省 **0.975357 ms**，包含动态输入／权重 pack 和回退 kernel 的启动。按 550 次 world 前向条件性外推仅约 **0.536 秒**，尚未计入新增初始化，也没有证明双卡版本获得同样收益。它验证了该算术可以接入整网并产生小幅净收益，单独不足以填补与领先成绩的差距。

完整 V2 视频质量试验随后已完成，结果未通过，详见下一节。该试验保留原 process timer、11 轮、50 步、23 个视频和官方质量工具；当前双卡生产成绩与本机正式材料均保留。

精确代码见 [model-r1](../experiments/fp16-balanced-residual-209/model-r1)，六组误差、42 个计时样本／条件、原 cache owner 证据与源码 SHA 见 [结果](../results/aggressive-20261028/fp16-balanced-residual-209/model-r1)。

## 完整 V2：质量未通过，未采用

完整单卡试验为 **316.602474 秒 / PSNR 24.786071095 dB**，11 轮、23 个视频与执行 profile 完整，整段 GPU 独占检查通过，但低于 V2 的 **25 dB** 门槛。官方工具返回质量失败，原始 log 和 JSON 一并保留。单卡时间与历史原始单卡 316.774396 秒仅差约 0.172 秒；这不是同次配对进程测量，不能据此宣称完整进程加速，更不能与当前双卡 289.486308 秒直接比较。

试验使用十个中间 world FFN 的残差近似，首样本校准固定，没有缩减 DDIM 步数或反馈工作量。局部 4.98e-6、完整单步约 2e-5～4e-5 的误差仍未能维持闭环视频质量，说明此前的局部筛选不足以预测最终 PSNR。该候选不能提交或替换正式实现；后续若继续量化，需要重新检验分层保护与跨 timestep 分布，不能重复未修改候选来宣称合格。

GPU 0 的 580 个遥测样本中，峰值温度 **71°C**、峰值显存 **73,364 MiB**，利用率至少 90% 时 SM 频率 **1320–1410 MHz**。未固定频率或调整功耗。公开[精确增量与生成器](../experiments/fp16-balanced-residual-209/full-quality-r1)及[完整单项 log／JSON、PSNR 与遥测](../results/aggressive-20261028/fp16-balanced-residual-209/full-quality-r1)，不发布生成视频、原始操作数或模型权重。

正式可用结果继续为 **V2 289.486308 秒 / 29.675324786 dB，五项合计 838.392232 秒**；本机 `GPU/runtime.log`、`GPU/result.json` 未被失败试验覆盖。
