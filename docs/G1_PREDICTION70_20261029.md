当前正式G1仍为 **155.314304秒／PSNR26.107156332dB**，五项合计 **738.805454秒**，五项均使用双A800。本轮两个时间步预测候选均完成完整工作量，但未通过25dB门槛，未替换正式log／JSON。

三次都执行全部11轮、每阶段50次DDIM更新、输出23视频，两rank视频一致，严格全程GPU守护clean。两个预测候选在不重叠的GPU对上并发执行；全刷新对照随后单独运行。它们不是同期同GPU交替AB，不用进程差值解释纯算子收益。对照只用于验证接入正确性，也未作为新成绩采用。

## 计算路径

从当前68文件G1版本接入，新增预测控制器和运行时，共70源码文件。保留全部原生FFN／GEGLU／attention数学与绑定辅助模块、原始完整GEMM描述符、根rank权重搬运及精确广播；只改协调器、图池配置和计时入口的新增生命周期钩子。没有新增原生CUDA参数或地址扫描。

完整刷新图继续使用原双卡分片及31个FFN绑定；复用图关闭分片，剩余浅层和head使用原生完整形状计算。专用绑定器仍只处理两个完整图，原31个FFN／62个GEMM的断言保留。全部四图中，完整图各31个分片，复用图各0个；两个完整图共62条捕获记录、124个Linear记录、两份原生绑定报告。空间与时间attention原有汇合边界检查同样保留。

预测使用最近两次完整刷新及真实位置间距；原预测算术、FP32残差运算与缓存作用域和此前已采用的非V2方案相同。在零起始位置`[20,40)`内隔步预测，每轮每阶段10次预测、40次刷新，两阶段各550调用／110预测。每次预测都仍执行原采样更新，预测结果不进入刷新历史。13块范围为input_start=6／output_end=6，23块为1／11。

全刷新对照只将预测stages置空，使用两张图、每阶段550次完整刷新、0次预测、0字节动态特征历史。新的协调器和显式步骤跟踪保留。23视频SHA与正式68文件版本逐一相同，证明这条全刷新接入路径保留了既有输出；不能因此推断开启预测后的精度。

## 精度证据

官方指标按整个分项RGB误差汇总，不能平均逐视频PSNR代替。逐视频标量曲线见[完整对照](../results/aggressive-20261029/g1-prediction70/trajectory-scalar-comparison.json)。例如world首轮，原68为46.3080dB，13／23块分别40.6558／38.9041dB；下一轮为43.1607、33.8754／34.1124dB。该现象与误差经闭环反馈放大相符，尚未分别隔离动作、状态与视频反馈的贡献。

后续应在全刷新路径上采集不改变输出的特征轨迹标量，比较预测误差，再决定高阶预测或保护范围；当前结果不支持继续直接扩大一阶深层预测窗口。

## 复现与核对

```bash
python reproduce/verify_g1_prediction70.py
~/.venv/bin/python reproduce/run_g1_prediction70.py --depth 23 --gpus 0,1 \
  --workdir /path/on/private-tmpfs/g1-predict23 \
  --storage-config /path/to/qualified-storage.json \
  --cache-dir /path/to/qualified-FFN-cache \
  --prediction-cache-parent /path/on/executable-filesystem
~/.venv/bin/python reproduce/run_g1_refresh_control70.py --gpus 0,1 \
  --workdir /path/on/private-tmpfs/g1-full-refresh \
  --storage-config /path/to/qualified-storage.json \
  --cache-dir /path/to/qualified-FFN-cache \
  --prediction-cache-parent /path/on/executable-filesystem
```

`--depth 13`复现13块候选。三份公开入口重建均在比赛机禁用CUDA，逐文件匹配实际计时70源码和资源。预测CPU检查包括1200次执行器调用、960／240个刷新／复用模式、3600个仿射预测输出以及环境和Triton缓存类恢复；对照另核对1200次全刷新调用、0次预测、max_graphs=2。完整GPU自检覆盖FP16／FP32、直接／残差预测、尾块和修改输入后的图重放。

两次早期CPU预检失败也保留：旧测试错误引用了63版本的FFN辅助模块；修复后原生缓存测试又遇到已满home的默认缓存路径。最终测试使用实验临时目录，原生缓存类检查通过。这两次均未执行GPU工作量，没有正式成绩。
