# 相邻时间步的差量 GEMM

该原型已完成真实相邻输入测量，并接入原209单卡V2的12个FFN。完整质量为24.828817829dB，未达门槛、未采用；没有新提交成绩。最新实测见[真实时间步试验](TEMPORAL_LIVE_TRIALS_20261029.md)。下面保留前三轮算子资格证据。思路来自[实际时间相关性测量](CROSSSTEP_REUSE_20261029.md)：一个真实FFN的high相邻步相关性很高，但低位补偿近乎不相关，直接缓存旧补偿反而更差。

## 算法与约束

完整刷新计算原始BK64补偿乘积，缓存其 **FP32、加bias之前** 的结果，以及由high/low重构的输入。复用时使用：

```text
当前乘积 ≈ 缓存乘积 + FP16(当前输入 − 缓存输入) × 静态权重
当前输出 = 当前乘积 + 当前bias + 当前残差
```

原型将输入差量乘以1/4再转Half，乘积按4缩放回来；该二进制比例避免有限Half输入对的差量溢出Half。它没有增加Half的普通数相对精度，收益依据是差量本身小于完整输入。

world中当前所有网络计算仍需进行；此方法只可能减少个别线性层的乘积数。没有缓存视频或整段特征，也没有减少任何DDIM位置。误差、质量和整网净收益都必须另外验收。

## 已完成的三轮算子检查

- r1：原始BK64完整刷新＋单独差量路径，显式保存／打包。6组形状和weight-low分支，48项精度检查。
- r2：设备端标志选择刷新或差量，两步可放在同一CUDA Graph；包含每个算子的flag写入成本。48项检查通过。
- r3：增加图外改变同一设备flag和输入、重放同一图的检查。刷新、复用、恢复刷新三个状态分别核对；6组共66项检查通过。

完整刷新、相同输入复用、零权重刷新要求逐位一致。1%／5%／20%变化输入、新bias／残差、权重恢复也已检查；局部最大相对L2误差约2.05×10⁻⁶。这个分母包含测试中的bias与残差，不能直接与只读测量中的纯乘积误差比较，更不能预测最终视频PSNR。weight-low为0和非0都保留独立分支。

## r3六对交替计时

时间单位为毫秒，**每次是两个算子调用的合计**：基线完整计算两次，候选完整刷新一次、差量计算一次。输入保存、差量打包、缓存读写、flag写入和epilogue都计入。

大形状、weight-low为0时，当前小范围约有11.6%的两步合计改善；不能把0.159983ms当作每一步的收益。该方法尚未覆盖整网所有线性层；少数owner的局部节省不能解释百秒差距。

## 后续真实验证与当前下一步

真实DDIM中49对普通Torch输入已测：纯乘积相对L2中位2.6203110×10⁻⁵、最大3.6626435×10⁻⁵；50次刷新逐位一致，原23视频SHA不变。四个时间位置的24对配对计时均更快，两次调用合计约省0.1614ms。该只读测量不代表完整输出替换后的质量。

实际runtime已经识别12个普通Torch owner、检查master身份／版本并管理条件／轮次失效。每次denoiser调用写一次设备flag，world仍保留同一张图，所有分配和初始化计入原进程。完整11轮、23视频结果为318.427327秒／24.828817829dB；world165次差量调用，quality失败。

下一步应定位需要保护的层级／阶段，或改进差量的近似精度，再重新验证完整质量与进程净收益。当前没有与225双卡结合，没有新的103视频汇总，也没有替换本机GPU双文件。不能因为只差约0.17dB就视为通过。
