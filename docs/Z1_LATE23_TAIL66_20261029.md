# Z1：23块晚区间预测，保留末端双卡分帧

在已采用的Z1 66文件版本上，把时间步预测从13块的`[10,40)`改为23块的`[20,40)`。完整12轮／25视频结果为 **132.539858秒／PSNR 30.332499792 dB**，两rank视频SHA一致，完整工作量和无外部上下文检查通过。此前正式版本为138.945151秒／28.992932876dB。

这次同时改变复用深度与开始位置：预测次数从每阶段每轮15次降到10次，但每次覆盖更多深层块。不减少轮数，也不减少任何50步DDIM更新；每步仍计算浅层、head和sampler更新。质量改善是这次完整闭环运行的实测结果，不能从复用深度直接推断其他任务的PSNR。

GPU0／2随后运行原13块66文件版本，完整 **138.280727秒／28.992932876dB**，25视频SHA与原正式结果全同。候选→对照这一组完整进程比较省 **5.740869秒**；只有一组同卡比较，未宣称多组独立配对。对照全部源码和计时资源哈希与原正式版本一致，使用全新输出及guard状态，未修改计时器。

## 改动范围

## 独立检查与受干扰尝试

公开入口已在比赛机禁用CUDA，精确重建实际66源码及计时资源；原FFN、3600个预测仿射输出、缓存环境及Triton全局类恢复、分帧和时间边界检查全部通过。新增实际12／12层结构测试核对23个父块、全部1200个仿射输出、24段50步、真实系数、持续执行的浅层／head以及RNG不变。CPU检查不代替上面的完整视频质量。

一次早期CPU测试在`Runtime.apply`返回后读取已经结束的`controller.current`，发生测试观察错误；改为按显式采样位置检查系数。该修复未改变推理代码，失败源码和日志也保留。

第一份GPU0／3运行被外部上下文干扰，计时排除。第二次尝试尚在等待，仅停止核实为自有的等待进程组；未向外部进程发送信号。以全新输出／守护状态在空闲GPU0／2重跑，66源码、全部计时资源及守护脚本SHA不变，得到本页完整结果。原始受干扰日志和`timing-contaminated.txt`保留，不能用作正式成绩。

候选206条遥测，两卡峰值均31600MiB、最高62／66°C；利用率至少50%的样本中，SM频率范围1335–1410／1260–1410MHz，中位1410／1380MHz。对照216条遥测，峰值均31198MiB、最高61／64°C，繁忙样本SM中位同为1410／1380MHz。完整遥测和标量汇总保留，不据此推断温度或频率对差值的因果关系。
