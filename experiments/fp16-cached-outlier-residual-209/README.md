# 按原 FP32 权重版本缓存量化残差权重

此目录比较已通过 PSNR 25.743336922 dB 的动态量化权重打包，与保留相同算术的静态权重缓存。这里的性能基准是此前的量化版本；不是原始 FP32 补偿模型。

十个中间 world FFN 缓存 INT8 权重、FP32 scale 和连续 Half 离群通道，共 72,140,800 字节。原 FP32 master 的指针、版本、形状、dtype、device 与原 Half cache master key 共同校验。Triton `out=` 写入不会增加 Half 张量版本，因此不能据此判断缓存是否新鲜。缓存 owner 由图执行对象持有，每次重放前检查，每次实际权重变化时重新打包；输入打包继续每步执行。

- `model-r1`：六组输入及 570 Linear、782 norm、192 Conv2d 参数修改／清零／恢复，18 个输出与动态打包版本逐位一致。每个缓存刷新五次，三份缓存与新打包逐位相同。六对计时仅三对更快，中位节省 -0.052734 ms，未证明稳定收益。
- `model-r2`：将每步重复的 70 次 stream 登记移到实际权重刷新时，保留完整 master 签名检查和图生命周期；同时改用六组、每组七个 ABBA／BAAB 交错周期，共每种条件 84 个完整前向样本。六组的配对周期差值中位数均为正，合计中位省 **0.322296 ms/world 前向**。同样通过 18 个输出逐位一致、五次刷新与全部 master 修改／恢复检查。实现与采样方法均有变化，不能把两轮差异单独归因于其中一项。

- `full-quality-r1`：完整单卡 V2 为 **322.518989 秒 / PSNR 25.743336922 dB**，11 轮、23 个视频完成，全部视频 SHA256 与此前动态打包版本相同。新增初始化、首次打包和每步签名检查均进入原计时器。但它比历史动态版本 321.720411 秒慢 0.798578 秒，两次不是配对进程测量，未证明整项加速。

目前未替换正式成绩。各目录脚本需要原始 209 文件源码、原 flags、原模型诊断启动参数及比赛授权资源；不包含模型、操作数或视频。完整版本的 `generated_assets.py` 从原始 evaluator 和 shell 生成两份精确别名，校验原始及生成文件 SHA256；安装 hook 位于原 `PROCESS_START_TIME` 之后，不能把该 hook 直接加入双卡版本后声称组合已验证。
